# YouTube 合集下载

在 YouTube 点击合集下的“查看完整播放列表”，复制含 `list=` 的链接，粘贴到下载中心。
系统只读取目录，完成后可“下载全部”或勾选需要的集数并“下载选中内容”。
新提交的合集自动展开目录；后续访问默认收起，按一个任务显示。

- 目录在独立后台线程读取完整列表，不再限制前 100 条。展开明细每页 50 集，接口最大每页 100 集。
- 下载中心按合集显示已完成集数、已选集数、总进度、当前下载集数和合计速度。
- 总进度按 `已完成 / 已选集数` 计算；选集下载完成后可继续下载尚未开始的内容。
- 媒体库按合集文件夹展示；展开后沿用每集的播放、分享、保存到当前设备和失败重试。
- “暂停合集”停止后续排队，当前下载中的集继续完成；“继续下载”恢复暂停或取消的集。
- “取消合集”停止已选但未完成的内容，已完成文件和未选集数保留；继续时只恢复已选内容。“重试失败”仅重新排队失败的集。
- 同一播放列表链接重复提交会打开已有合集；“检查更新”重新读取目录并追加新视频 ID。
- 重启后恢复未完成下载和未完成目录读取；暂停、取消的合集不会自动恢复下载。

文件保存在下载根目录的 `合集/合集名称 [合集ID前8位]/`，文件名为
`0001 - 视频标题 [视频ID].mp4`。合集改名或重新读取不会改变已经确定的保存目录。
优先选择 MP4/H.264/AAC，并按选择的画质限制最高分辨率；不做重新编码。
若来源不提供匹配的格式，该集会单独失败，其他集继续下载。

新增 `Collection` 表以及下载记录的 `collection_id`、`collection_index`、`collection_video_id`
可空字段。原有记录不会被转换或修改。现有下载器、Cookies、代理、播放接口和分享权限继续复用。
合集列表返回聚合数据，展开时才读取分页明细；前端不接收服务器绝对文件路径。

管理员登录保护覆盖所有合集 API。目录只接受规范化后的 YouTube 播放列表地址；
目录里的每个条目按视频 ID 重建 YouTube 单视频地址，不接受第三方指定下载地址。
选集接口仅接受属于该合集的记录 ID。每集在数据库中的状态由独立任务维护，
同一集只有一个下载线程能领取，避免取消/继续造成重复下载。

测试：`python -m unittest discover -s tests -p 'test_*.py' -v`。
覆盖超过 100 集的分页、选集、重复链接、追加更新、暂停/继续/取消/重试、
旧数据库迁移、访问权限、目录限制及现有播放、分享和下载测试。
